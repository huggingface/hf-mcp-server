### Boundaries that apply throughout

- `hf_fs` is Hub discovery/file reading, not a terminal, arbitrary HTTP client, SQL engine, or client-local filesystem.
- `hf_fs_write` can publish individual files and real repository PRs. It does not administer Space hardware/secrets or automatically upload local directories.
- `create_repo` supports creation/duplication/visibility/Space SDK, not hardware allocation, secrets, or running-instance administration.
- Jobs and Sandboxes make substantial workflows achievable, but introduce explicit remote execution, dependency setup, billing/entitlements, credential forwarding, and artifact persistence.
- A sandbox is **not** the user's computer, AWS profile/SSO cache, or the shell of their running Space.
- Reading `skill://…/scripts/example.py` does not stage that file or its sibling dependencies into a Job/Sandbox.
- `dynamic_space` invokes supported existing MCP-enabled Spaces; current implementation selects the first tool and restricts complex schemas. It is not generic Space administration or a browser.
- Successful submission, process exit, API invocation, model publication, and user-visible application correctness are distinct checks.

## Concrete incompatibilities found

These findings are from shipped source, not hypothetical adaptation concerns.

1. **Outdated or unavailable tool names and schemas.** LLM/vision examples refer to `hf_doc_search`, `hf_doc_fetch`, `dataset_search`, `AskUserQuestion`, old skill names, and unsupported `include_readme`. Use the actually advertised tools, and `hf_fs cat` for README files. `hugging-face-jobs` is not a skill in this catalog.
2. **Jobs calls need actual JSON envelopes.** `hf_jobs("uv", {...})` is pseudocode, not the API. Use `{"operation":"uv","args":{...}}`, string timeouts, explicit `with_deps`, and inspect the actual returned result.
3. **Do not submit client-local paths.** UV receives its path inside the remote container. Stage files, use accessible raw source URLs, or inline code. Inline detection currently relies on a newline; the source schema's “local file path” wording is misleading.
4. **Credentials must be explicit.** Jobs supports the exact HF-token placeholder in secret maps; Sandbox offers explicit token forwarding. Arbitrary environment names are not generically substituted. Avoid `hf auth token`, raw token reads or putting tokens in generated application files.
5. **Paper publisher PR safety defect.** `huggingface-paper-publisher/scripts/paper_manager.py:166–177` prints “PR creation not yet implemented. Committing directly.” Use the real PR path instead.
6. **Training observability/persistence promises exceed some templates.** Vision scripts initialize Trackio without `space_id`; default sentence-transformer outputs can remain local, and final push failures can be caught. A successful training process is not enough: verify artifact existence and access.
7. **Local/cloud category errors.** AWS local profiles, hardware, localhost, browser behavior and local caches cannot be inferred from remote HF compute.
8. **Stale/internal guidance.** Best-model fallback refers to a curated table that is absent; ZeroGPU guidance conflicts over runtime `nvcc` and `spaces` requirements. Reconcile these rather than mechanically rename tools.

## Recommended catalog strategy

1. **Publish MCP-specific variants, not a blind mirror.** Keep upstream as source material. Rewrite examples against tested tool schemas; regenerate complete manifests/digests/sizes after adaptation.
2. **First read-only pack:** papers, dataset inspection, Hub discovery; model recommendation only once benchmark retrieval is genuinely supported.
3. **First write/deployment pack:** Gradio and Spaces repo publishing, repaired citation-link PRs. Mark hardware/secrets/lifecycle and browser QA prerequisites explicitly.
4. **First compute pack:** LLM, vision and sentence-transformer training; share one Jobs/persistence/Trackio adapter. Add `hf-mem`, tool building and evaluation next.
5. **Optional AWS pack:** keep the six SageMaker/AWS skills together and require explicit AWS execution context, credentials, permissions and cost/cleanup handling.
6. **Optional local/browser pack:** keep local-model and Transformers.js runtime instructions only where the host actually supplies those capabilities, or expose clearly advisory variants.
7. **Make discovery capability-aware.** Curate `skills/list` against the active tool selection; do not infer tools from login alone. Keep direct retrieval behavior and serving metadata consistent with the specification. This is a product decision, not a spec-mandated capability-negotiation feature.
8. **Do not claim usage from retrieval.** Existing telemetry can show metadata probes and file retrievals. Success criteria for these workflows need separate publication/job/application checks.

No runtime or catalog configuration was changed during this review.
